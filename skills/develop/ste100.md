# Writing standard: ASD-STE100 with an expanded vocabulary

Write all prose in ASD-STE100 Simplified Technical English (Issue 9). This applies to chat replies, summaries, plans, reviews, commit messages, pull requests, issues and documents.

## Input

- Read the owner's input as STE. Give each word its STE meaning. If a word has two possible meanings, use the technical meaning.
- Do not rewrite or correct his input. Do not repeat it back to him.
- If his input is not clear, ask one short question.

## Vocabulary

- Use STE approved words with their approved meanings.
- You can also use these words (the expanded vocabulary):
  - technical names: names of products, tools, files, commands, settings, accounts, machines, people and projects;
  - technical verbs: verbs that are usual in software and operations, for example: commit, merge, deploy, install, configure, restart, log in.
- Use one word for one meaning. Use the same word for the same thing each time.
- Do not use slang, idioms, jokes or filler words.

## Sentences

- Write procedural sentences of 20 words or less. Write descriptive sentences of 25 words or less.
- Write one instruction in each sentence. Write the instructions in the sequence of the steps.
- Use the imperative for instructions. Use the active voice.
- Use only these tenses: simple present, simple past and simple future.
- Do not use "-ing" words as verbs. Do not make nouns from verbs.
- Do not use phrasal verbs. For example, write "start", not "fire up".
- Do not use more than three nouns in a cluster.
- Keep "the", "a" and "this" where they make the meaning clear.

## Paragraphs and structure

- Write one topic in each paragraph. Write six sentences or less in each paragraph.
- Use a vertical list for a sequence of steps or for three or more items.
- Put a warning or a caution before the step that it applies to. Start it with the instruction, then give the risk.

## Length

- Give only the information that the reader needs. Do not write an introduction. Do not repeat the request.
- Give the result first. Then give the necessary details.

## Exceptions

Do not change these items to STE:

- code, commands, paths, identifiers, logs, error messages and data;
- quoted text;
- text where a repository rule, a check or a recipient sets a different format, for example customer pages, legal text or outward work that must read as the owner's own writing.
